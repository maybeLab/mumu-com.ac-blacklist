# 已知问题：禁用原输入法影响中文输入及远程控制

记录日期：2026-11-03。来源：用户使用反馈。本次只记录现象和现有方案边界，未连接模拟器复测；不将反馈冒充为新采集的设备日志。

## 用户反馈

禁用模拟器原输入法后，出现以下功能问题。此项目中的原输入法为内置搜狗：

`com.sohu.inputmethod.sogou.chuizi/com.sohu.inputmethod.sogou.SogouIME`

| 使用场景 | 用户反馈的影响 |
| --- | --- |
| 模拟器内输入 | 无法输入中文 |
| UU 远程控制 | 无法正常输入中文、弹出输入法等 |
| MuMu 模拟器 APP 远程控制 | 无法正常输入中文、弹出输入法等 |

状态：**已知未修复问题**。具体受影响的系统版本、远程客户端版本和输入模式尚未重新采集，暂不扩展为所有 MuMu 环境均会出现的结论。用户反馈指出禁用原输入法与这些问题相关，底层依赖机制尚未进一步定位。

## 对现有修复方案的影响

原 `module/service.sh` 以及分享包沿用的 `service-core.sh` 在解除黑名单、切换按键精灵之后，会执行 `ime disable` 停用上述搜狗输入法。Windows 安装入口还将“搜狗不在启用列表”作为成功检查的一部分。

因此，现有成功标记和默认输入法回读，只能反映这套脚本的目标状态，**不能证明本地中文输入、UU 远程或 MuMu APP 远程输入均可用**。26 项本地模拟测试也没有覆盖这些真实输入场景。

2026-10-29 保存的中文测试，调用的是按键精灵应用自身的文字提交辅助方法，验证了该输入连接的提交链路。它没有测试宿主端手动中文输入、两种远程控制或输入法面板弹出。保留原测试证据，同时缩小其结论范围；不能据此宣称所有中文输入功能已经恢复。

## 现有恢复入口

- 使用一键工具的用户：运行 Windows 工具的 `恢复原设置.cmd`，恢复本设备首次安装前的输入法配置并停用模块。
- 使用原设备专用版的用户：按 [原方案回退流程](04-operation.md#3-恢复原设置与停用模块) 执行已保存的恢复入口。

只在管理器中停用模块不会立即重新启用原输入法或恢复当前配置。恢复后仍须分别核对模拟器内中文、UU 远程中文和面板弹出、MuMu APP 远程中文和面板弹出；本次尚未执行这些恢复后的复测。

## 后续验证要求

后续调整方案时，需要单独验证“保留原输入法启用，仅切换默认输入法”的可行性，不能继续把停用原输入法当作完整功能验收标准。以下均为待测项，不是已经实现或通过的结果：

1. 记录系统、远程客户端版本，以及默认、启用列表和实际绑定的输入法。
2. 在原输入法启用且为默认时，建立本地和两种远程输入的基线。
3. 在保留原输入法启用、默认切换按键精灵时，分别验证自动化提交、本地中文输入和两种远程输入。
4. 分别测试中文提交、点击输入框后面板弹出、手动唤起面板；实际核对输入框文字，不能只看命令成功。
5. 对比禁用原输入法时的现象，并检查重启、恢复原配置之后的行为。

当前记录没有调整脚本的停用逻辑，也没有确认“保留启用”已能解决问题。
